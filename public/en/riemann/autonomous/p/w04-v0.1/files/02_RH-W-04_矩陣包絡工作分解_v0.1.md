# RH-W-04: Real Weil Matrix Enclosure Work Breakdown

**Version:** v0.1  
**Status:** `SPECIFICATION_COMPLETE / ENTRY_ENCLOSURES_OPEN`

---

# 1. Objective

For a fixed support radius $a$ and a finite real basis $\phi_1,\ldots,\phi_m$, generate a rational interval matrix:

$$
M_{ij}=Q_a(\phi_i,\phi_j)
\in
[\underline M_{ij},\overline M_{ij}].
$$

The final verifier will not accept:

- Single floating-point values;
- Only specifying the number of decimal places without an error proof;
- Using the agreement of two floating-point programs as an interval proof;
- Verifying only a finite sum over zeros without a truncation bound;
- Directly treating a negative numerical eigenvalue as a counterexample to RH.

---

# 2. Prioritizing the Arithmetic / Continuous Kernel Side

Finite support makes the prime terms finite. For functions supported on $(-a,a)$, translation correlation only involves:

$$
\log n\le2a,
\qquad
n\le e^{2a}.
$$

Therefore, the matrix elements can be decomposed as:

$$
M_{ij}
=
M^{\rm endpoint}_{ij}
+
M^{\rm arch}_{ij}
+
M^{\rm prime}_{ij}
+
M^{\rm rem}_{ij},
$$

where `rem` is only allowed to represent a well-defined continuous kernel or normalization correction; it is not allowed to represent a bucket for unknown errors.

Each term must output its own interval, which are finally combined using rational Minkowski addition.

---

# 3. Sub-Work Packages

## 3.1 `ENTRY-ENDPOINT`

For a general complete kernel, strictly enclose the endpoint functional. If an endpoint-null subspace is adopted, the vanishing of the endpoint terms must be proven by analytic identities rather than floating-point near-zero values.

## 3.2 `ENTRY-PRIME`

Enumerate:

$$
n\le e^{2a}
$$

all non-zero von Mangoldt terms. Every constant:

$$
\log n,
\qquad
n^{-1/2}
$$

and translation integral must have a rational interval.

The following must be preserved:

- The list of primes/powers;
- A proof of completeness or a replayable sieve;
- The interval for each term;
- A guarantee that the summation order does not affect the final rational enclosure.

## 3.3 `ENTRY-ARCH`

Handle the Archimedean terms generated by the gamma factor or the screw-function continuous kernel.

Acceptable methods:

- Arb/MPFI-like directed rounding ball arithmetic;
- Gauss/tanh-sinh quadrature with analytic remainder bounds;
- Piecewise Taylor models;
- Rational upper and lower Darboux sums that can be replayed in an independent small verifier.

Error estimates from standard `mpmath.quad` are not accepted as formal certificates.

## 3.4 `ENTRY-SINGULARITY`

Apparent singularities at $x=y$ or $x=1$ must first be analytically eliminated before performing interval computations. Directly dividing an interval by a denominator containing zero is strictly prohibited.

## 3.5 `ENTRY-HERMITIAN`

Under a real basis, the matrix should be real symmetric. During computation, only the upper triangular intervals are generated and then mirrored; if two independent paths generate disjoint intervals, the certificate must fail.

## 3.6 `ENTRY-HASH`

All basis definitions, parameters, formula versions, programs, and data attachments must output a SHA-256 hash. Certificates only reference hashes; "files with the same name are considered identical" is not allowed.

# 4. Separation of Search and Verification Layers

## Search Layer

May use:

- NumPy/SciPy;
- Automatic differentiation;
- AI parameter search;
- Arbitrary precision but non-rigorous computation;
- Generalized eigenvalue solvers.

The output is merely a candidate:

$$
(a,N,v_{\rm float}).
$$

## Verification Layer

Only accepts:

- Rational witnesses;
- Rational interval matrices;
- Verifiable attachments;
- Specified versions of normalization contracts.

The verification layer does not execute floating-point eigenvalue solving.

---

# 5. Minimal Certificate Strategy

The first version does not attempt to verify all eigenvalues of the matrix. It only computes a scalar for a single rational witness $c$:

$$
U_M(c).
$$

This reduces the goal of rigorous numerical work from a "high-dimensional spectral enclosure" to "a finite number of matrix element intervals and a rational sum."

Furthermore, sparsification can be performed along the support of the witness: if $c$ has only $r$ non-zero components, it only requires:

$$
\frac{r(r+1)}2
$$

matrix element intervals, rather than the complete:

$$
\frac{m(m+1)}2.
$$

Therefore, the candidate searcher should simultaneously optimize:

$$
\text{negative margin}
\quad\text{and}\quad
\text{witness sparsity}.
$$

# 6. Acceptance / Rejection Rules

## Acceptable as `CERTIFIED_NEGATIVE_WITNESS`

- All utilized $M_{ij}$ have strict rational intervals;
- The witness is a non-zero rational vector;
- The exact verifier obtains:

  $$
  U_M(c)<0;
  $$

- Normalization, basis, and attachment hashes are complete;
- The certificate explicitly indicates the real zeta Weil form.

## Only Markable as `NUMERICAL_CANDIDATE`

- Uses floating-point matrices;
- Only has self-reported errors from the integrator;
- Only has negative eigenvalues and residuals;
- Uses finite zeros but lacks strict tail bounds.

## Must be Marked as `REJECTED`

- The sign contract is unclear;
- Endpoint terms are missing;
- The basis or support is not fixed;
- The upper and lower bounds of the interval are reversed;
- The witness is all zeros;
- The upper bound of the interval cannot be strictly less than zero.

# 7. Next Round Priorities

The next round should not initially expand the matrix dimension, but rather select a minimal basis, such as $m=2$ or $m=3$, to complete the first end-to-end pipeline of **real Weil element intervals**:

1. Fix $a$;
2. Fix two real cutoff-Fourier bases;
3. Rigorously compute $M_{11},M_{12},M_{22}$;
4. Cross-check with high-precision non-rigorous implementations;
5. Even if there are no negative values, save the complete error budget and replay files.

This milestone is not about finding an RH counterexample, but rather proving that the matrix enclosure engineering can actually work.
