RH-W-18: Unified Certificate Backend and Single Verification Entry

The certificate schemas, dependencies, and completeness accumulated progressively from W-05 to W-17 are inconsistent — this package establishes a single CLI (rhcert.py) and a five-tier trust vocabulary to natively replay the verifier of each round one by one. The results are not all green: W-06 is marked as LEGACY_INCOMPLETE due to a missing 2×2 JSON in the public directory, and W-14 is marked as SUPERSEDED_RECERTIFIED due to a missing term in the original derivation — this is exactly the reason for the backend's existence.

RH_CLAIM = False — The claim status output by the verifier inside the package itself, reproduced exactly as is. The unified manifest fixes allowed_global_conclusion=FINITE_CERTIFICATE_BACKEND_ONLY; if the manifest is changed to RH_CLAIM=true, the verification will still reject it even if the hash is recalculated.
